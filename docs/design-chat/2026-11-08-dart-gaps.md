## 1. Cause 1 — exact-name matching of income-statement lines (261 companies)

**Where:** `fetch_data.py`
- `parse_dart_list` lines 1314–1320: `rev` only for `매출액 · 수익(매출액) · 영업수익`, `op` only for `영업이익 · 영업이익(손실)`, `ni`
  only for `당기순이익 · 당기순이익(손실) · 연결당기순이익`. Only spaces are removed. `acct_name()` (which strips `Ⅰ.` `(1)` `1.`) exists
  but is used only for 자본금. No `account_id` is used, and there is no `sj_div` restriction for these three.
- Line 1378: `_fin` (the three-year amounts **and** eq, li, cash, ocf, ca, cl …) is kept only if rev/op/ni matched. That is why
  카카오뱅크 shows `debt` (from 부채총계/자본총계) but no equity or anything else.
- `parse_dart_quarter` lines 1518–1521 is even narrower: `op` only `영업이익` (not even `영업이익(손실)`), and `ni` only
  `당기순이익 · 당기순이익(손실) · 분기순이익 · 반기순이익`.
- `dart_financials` line 1575: a CFS whose income lines did not parse but whose `debt` did is still "found", so the year
  stays 2025 (correct) with blank lines.

Across 24 sampled statements the misses split: numbered prefix 22 lines (rev 7, op 8, ni 7); variant words 25 lines
(`매출` 7, `당기순손익` 5, `영업손익` 4, `영업손실` 3, `당기순손실` 3, `영업순손익` 1, `보통주 당기순이익` 1, `매출및지분법손익` 1).

and were missed. Only 2 non-financial lines are truly absent (파로스아이바이오 revenue, 해성옵틱스 net income).

**Proposed fix** (prototype run on the 24 statements finds every non-financial line):
1. For rows with `sj_div` in `IS`/`CIS` only, take the first row whose `account_id` is `ifrs-full_Revenue` (rev);
   `dart_OperatingIncomeLoss` or `ifrs-full_ProfitLossFromOperatingActivities` (op); `ifrs-full_ProfitLoss` (ni);
   `ifrs-full_ProfitLossAttributableToOwnersOfParent` (nio).
2. Fallback for `-표준계정코드 미사용-` rows: `acct_name()`-normalized names, with the sets extended to
   `매출`, `매출및지분법손익`; `영업손실`, `영업손익`, `영업순손익`; `당기순손실`, `당기순손익`, `연결당기순이익(손실)`; and for quarters
   `분기/반기순손익`, `분기/반기순손실`, `연결분기/반기순이익`. **Do not** use a name fallback for nio: in CIS the same name
   (`지배기업의 소유주`) is used for comprehensive income (`…ComprehensiveIncomeAttributableToOwnersOfParent`), and in some
   responses that row comes first.
3. Keep the balance-sheet fields when no income line is found (line 1378), and log the count loudly
   ("손익 줄 못 읽음 N곳: …").
4. Same rules in `parse_dart_quarter`.
5. Product note for Jack: for brokers, banks and VC firms the matched revenue is `영업수익` (gross, interest included), so
   영업이익률 and EV/매출 are not comparable with industrial companies. Financial companies are already outside EV (`FIN_SECS`).

**Re-read:** needed. The DART cache (`.dart-cache/dart-v2.json.gz` in the GitHub Actions cache, key prefix
`dart-cache-v2-`, 14,031 entries / 0.6 MB, last saved by run 42393182400) stores each entry's **parsed** result (`d`),
not DART's rows. It also has no download API (the dry-run artifact carries only the four JSON files). So nothing can be
re-parsed from it. The annual entries alone (~291 companies) would fit the v19.1e redo mechanism (`redo=(tag,
predicate)`, 800 per run). Causes 1 and 2 together, though, touch nearly every annual statement entry and all quarterly
entries (~5,000), which amounts to a full re-read. **Recommendation:** merge the parser fix before v19.1f's planned `dart=full` run,
so that one run of the day re-reads everything with the new parsers. Expect a few hundred more quarterly calls (TTM for ~290
companies that had no `_fin`): ≈13,600 estimated, still under the 16,000 target. Do **not** bump `DART_CACHE_VERSION`: that
empties the cache and re-reads KSIC too (+2,411 calls).

**Gate row that would have caught it** (new, stricter only):
- "국내 손익 줄 채움 — 시총 상위 200": share with current-year 매출 (financial companies excluded), 영업이익, 순이익.
  **Today 88.4% / 93.0% / 90.5%.** Suggested FAIL < 98% for each (set from the post-fix dry run).
- Same for all companies with fy = 2025 and DART statements: today 93.8% / 95.7% / 95.2%; suggested FAIL < 99%.
- "필수 종목 손익 3줄": every must-have has rev (except financial)/op/ni. **Today 한화에어로스페이스 (012450) has no revenue →
  FAIL.**
- The pipeline exports a count "재무제표는 있는데 손익 줄을 못 읽은 회사" (BS parsed, no IS line), next to `divCheck`; the gate
  fails above 0 among the top 500 and names them. Today: 32 (the cause-1 companies with no income line at all).
- Optional cross-source row (1 DART call per run): top 100 rev/op/ni equal to `fnlttMultiAcnt` within 1%.

## 7. Cause 7 — dividend table stock-kind variants (8 companies)

**Where:** `parse_dart_dividend` line 1477 (`if knd and knd not in DASHES and "보통" not in knd: continue`). The same test sits
in `parse_dart_basis` line 1452, which therefore **counts common-stock rows as preferred classes** (`pdps`). That can trigger
needless share-count calls and wrong dividend-basis weights.

| stock_knd in DART | Companies | 2025 DPS in the table |
|---|---|---|
| `의결권 있는 주식` / `의결권있는주식수` | KCC, KCC글라스, 신라교역 | 15,000 · 1,600 · 500 |
| `보 통 주` (spaced) | 네패스 | `-` (= 0, no dividend) |
| `결산배당` + `중간배당` rows | 에스피지, 풍국주정 | 150 + 100 = 250 · 200 (+ `-`) |
| `대주주` / `소액주주` (different dividends by holder) | 남화산업, 송우인포텍 | 200/200 · `-` (2024: 대주주 30,000, 소액주주 `-`) |

**Fix:**
- Remove spaces from `stock_knd`.
- Common = contains `보통`, or `의결권있는` without `없는`, or blank/`-`. Preferred = `우선` / `의결권없는` / `종류`.
- Rows naming the dividend type (`결산`/`중간`/`분기`) are common-stock rows: sum them per year.
- For `대주주`/`소액주주`, use the 소액주주 figure (what an ordinary investor gets) and flag the different-by-holder dividend.
  This is a product decision for Jack.
- Apply the same classification in `parse_dart_basis`.

**Cache:** the DIV2 entries are parsed. Use a redo with tag `div3` and the predicate "000 entry with no `dps`": about 8–25
calls in one cache run (or the full run).

**Gate:** split `divCheck.noDps` into "no table" vs "table but no common row". FAIL when the second is > 0 among the top
500 (today 8, incl. KCC at market-cap rank 128).

## 8. 우선주 (59) — field by field

## 9. Halted / no-trade stocks (71, not 3)

What the data has:
- In the KRX listing file there is **no halt flag**. A no-trade day looks like `Volume 0`, `Open/High/Low 0`, `ChangeCode 3`,
  `Changes 0`, `Amount 0` (the `Dept` column shows 관리종목 / 투자주의환기종목 for many).
- 71 published stocks had zero volume on 11-06; 67 of them also on 11-05 (long halts: 금양, 삼부토건, EDGC, 이오플로우 …).
- In `data.json`, `val` = 0.0 and `d1` = **0.0** for 69 of them; there is no field saying the stock did not trade.
- 8 are KONEX names without trades; a KONEX price can still move without a trade (EMB −5원, so "no trades" ≠ "halted").

The audit's three:
- **STX**: no trade on 11-06. The price is re-based from 3,530 to 18,360 (shares 31.0M → 28.7M, market cap 1,095억 → 5,263억)
  after a capital change, so "11월 6일 종가" is a reference price. d1 is blank (±30% rule), and r1 +420%, MDD −83%,
  volatility 248% are artefacts.
- **인지디스플레, 에쎈테크**: they **traded** on 11-06 (24,094 and 15,292 shares) after a 5:1 consolidation (shares ×0.2).
  - d1 is blank because 726 → 3,030 exceeds ±30%; KRX's own `ChagesRatio` says −16.53% / −18.78%.
  - The 52-week low (`lo` 726 / 591 = the unadjusted 11-05 close), MDD −94% / −92% and volatility ~190% are wrong.
  - Cause: the "pin the last 19 sessions to official closes" step (`fetch_data.py` ~2820–2840, log "39,915개 봉 · 2,340종목")
    writes unadjusted listing closes into a series that is otherwise split-adjusted.

**Fix:**
- `noTrade: true` when the pxDate listing row has Volume 0 and Open 0. Its d1 is blank (not 0.00), and the app shows e.g.
  "11월 6일 거래 없음 (거래정지일 수 있어요)" (Korean via Jack).
- When the listing `Stocks` changed by a clean ratio between sessions, take d1 from KRX `ChagesRatio`, and scale (or skip)
  the pinned closes before that date.

**Gate:**
- "거래량 0 종목 = noTrade 표시 · d1 빈 칸" FAIL when any differs (today 71 / 71 differ).
- "상장주식수가 깨끗한 배율로 바뀐 종목의 52주 저가·MDD" WARN naming them (today 인지디스플레, 에쎈테크).
