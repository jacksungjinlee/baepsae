## Decisions Jack makes before work starts

Claude Code asks these in Plan mode, recommendation first, and writes the answers into this file in the first PR.

1. **May an AI model read report text?** Recommended: **yes**, under every check in Part A.
   - It needs an `ANTHROPIC_API_KEY` Actions secret and a monthly spending cap. Jack sets the cap after seeing the estimate.
   - If no: only table parsers run. Coverage will be much lower, because region and customer tables differ by company.
     The themes that need text (Part E, types R and P) are dropped.
2. **Theme tag rule.** Recommended: a company gets a theme only if its latest report shows **current revenue** from

   never count.
   - Exception: drug themes may tag a candidate in **clinical phase 2 or later**, named in the report. The app labels
     it "개발 중".
3. **Fuzzy themes.** 1인 가구, 고령화·요양 and 금리 인하 수혜주 have no clean definition.
   - Recommended: keep the definitions in Part E and show Jack the member list in the PR.
   - Jack drops any theme whose list looks wrong to him.
4. **When may a number read from report text put a stock in 규칙 깨짐?**
   - Recommended: **only when two independent readings agree** (the two-key rule, Part A6).
   - Alternative: never. Numbers read from text then stop at 지켜봐요.

## Goal

Some rules and screens need facts that only exist as sentences or tables inside reports:
- China revenue share, CET1, K-ICS and occupancy;
- a company's own promises;
- which themes a company really belongs to.

Read each new document **once per stock, shared by all users**, and keep the exact sentence each number came from.
Never publish a value that fails a check. Ship as separate PRs: A → B → C → D → E.

## Part A — The reading machinery (first PR, no new user-facing data)

1. **Documents.**
   - **Korea (DART):** 사업보고서, 반기보고서 and 분기보고서, via the original-document API (one call per report).
   - **US (EDGAR):** 10-K, 10-Q, and 20-F for foreign issuers such as NVO. Use the `SEC_USER_AGENT` secret and respect
     SEC's rate limit.
   - **Promises (Part B):** also 기업가치 제고 계획 filings and dividend-policy announcements (KR), and earnings releases
     filed as 8-K exhibits (US). Many promises appear only there.
   - **Scope:** every stock in `data.json` (KR and US). Held stocks below the liquidity floor need facts too: the server
     can't know what users hold (`REDESIGN.md` §5).
   - **Queue order:**
     1. must-have stocks;
     2. stocks with an industry module (Part C);
     3. stocks above the liquidity floor;
     4. the rest.
2. **Find the section first.** Locate the named section by its heading, for example "II. 사업의 내용 › 매출 및 수주상황".
   - Only that section goes to a parser or the model.
   - Log the section found, or "section not found".
3. **Table parsers and the model.**
   - Deterministic parsers handle the standard tables: revenue by product, revenue by region, order backlog, capital
     ratios.
   - **Status fields** are numbers read from text that a rule can turn into 규칙 깨짐: CET1, K-ICS, occupancy,
     investment-grade tenant share, and the numeric target in a stated return-ratio policy (for example 코웨이's 40%).
     The executed return ratio is structured data from v18.0, not text. For these, run **both** the parser and the model (if Decision 1 is yes), so the two-key rule can
     work.
   - For every other field, the model runs only where the parser finds nothing.
   - Model settings: temperature 0, JSON output against a fixed schema, no tools. Store the model id and a
     prompt-version hash with every value.
4. **Checks every value must pass, or it is not published:**
   - **The quote is in the source.** The quoted sentence or table row exists in the source section, as an exact
     substring after whitespace normalisation. Every new value is checked in the same run (100%), and the result is
     stored with the value.
   - **Numbers come from the quote.** Every number in the value appears in the quote.
     - Code does the unit conversions and reads "△" as a minus sign, never the model.
   - **The period is right.** The report period matches the document.
   - **The denominator is fixed.** Every share is a share of **consolidated (연결) revenue for the same period** from
     v18.0, unless the field says otherwise.
   - **Region tables** need extra care:
     - Exclude intra-group and consolidation-adjustment rows (내부거래, 연결조정).
     - A table is `complete` when its named regions cover ≥ 95% of consolidated revenue; otherwise it is `partial`.
     - A broad region such as "아시아" with no China line means the China share is **unknown**, not 0.
   - **Bounds:** shares 0–100%; CET1 0–30%; K-ICS 0–1,000%; occupancy 0–100%.
   - **Unknown is never 0.**
     - A rule that needs an unknown value shows "확인 불가".
     - The 빼기 switch does not remove unknown stocks, and says how many it couldn't check.
     - A data-rule theme (Part E, type D) never tags on an unknown value.
   - **"Not reported" is a valid answer**, and must be returned when the source has no such figure. A value invented for
     a company that reports nothing is the worst error this task can make.
5. **Provenance on every value:**
   - document id (DART rcept_no or SEC accession) and section heading;
   - the quote;
   - report period and filing date;
   - method (`parser` or the model id), extraction date and check result.
6. **The two-key rule (Decision 4).**
   - On its own, a status-field value read from text can put a stock in **지켜봐요**.
   - It can put a stock in **규칙 깨짐** only when two independent readings agree: the parser and the model, or the same
     figure in two places of the document. Otherwise the stock goes to 지켜봐요 with "확인 필요".
   - Either way, the screen shows the quote and a link to the document.
   - Report text is untrusted input. The model has no tools, and its output is only data checked against the source.
7. **Freshness**, per field and per company, using the company's own fiscal year end.
   - A value is valid until the legal deadline for the next report that would update it, plus 30 days. Example: a Q3
     CET1 figure is valid until the annual report's deadline plus 30 days, not until June.
   - After that it is `stale`: rules that use it show "확인 불가" and change no status (`REDESIGN.md` §2.4).
   - Never use a stale value silently.
8. **Runs.**
   - **Daily:** process every new filing since the last one processed.
     - Save a marker (the last DART rcept_no and EDGAR accession done), so a failed run loses nothing.
     - A corrected filing (기재정정, 10-K/A) replaces the original's values. Keep the old ones in history with a
       "replaced by" link.
   - **Backfill:** the latest annual report, plus the latest quarter for status fields, for every stock in scope.
     - Stay within a fixed per-run budget shared with v18.0's OpenDART budget.
     - Peaks come in March (annual reports) and in May, August and November (quarterly). Work the queue in the order
       above, and log its length every run.
   - **If the model API fails:**
     - keep the previous values (they carry their dates);
     - log loudly with counts, and let the freshness rule decide;
     - never record a failure as "not reported", and never cache it.
   - **Cache:** key on (document id, prompt version, model id), so re-runs cost nothing.
     - Changing the model or the prompt means passing the accuracy check again before its values are published.
9. **Cost cap (if Decision 1 is yes).** Count tokens on every run and stop at the run's share of Jack's monthly cap.
   - Log the spend and the remaining queue in every run summary.
   - Reaching the cap is not a run failure, but it is visible.
10. **Accuracy check: the gate for Parts B–E.** Build a labelled set before any value is published.
    - **Set:** about 80 Korean and 30 US documents. Cover every module in Part C, with both "reported" and "not
      reported" cases. `tests/fixtures/extraction/` keeps only the extracted sections and the labels, not whole reports.
    - **Labels:**
      - Two separate agents label each document from the source, with the quote.
      - Code checks that every label's quote is in the source and that its number is in the quote.
      - Disagreements are settled by re-reading the source.
      - For standard tables, a parser-made label set is a third, independent check.
    - **Size:** at least 30 labelled values per field, at least 10 of them "not reported". Where fewer exist (for
      example, Korean REITs), use all of them and say so in the PR.
    - **For Jack:** the PR lists 10 random labels with DART or EDGAR links, so he can open two or three on his phone.
    - **Bar per field:**
      - numbers ≥ 95% exact, to the report's own rounding;
      - **0 invented values** and **0 quotes not found in the source**;
      - theme tags: precision ≥ 90% and recall ≥ 80% on the labelled pairs.
    - **A field that misses the bar ships as "not available".** The bar is never lowered to make it pass.

## Part B — Facts every company gets

- **Revenue by region**, by country where reported (중국, 미국, 국내 and so on), with the overseas share. It feeds:
  - the 중국 매출 비중 rule;
  - the 빼기 switch "중국 매출 30%+";
  - the themes K-푸드, 원화 약세 수혜 수출주 and 미국 내수.
- **Largest product or segment share** of revenue.
- **Largest customer share**, where reported (주요 매출처). Used for 주의할 점.
- **Order backlog** (수주 잔고) with its date, where reported, and backlog ÷ last year's revenue.
- **Company promises** (회사가 한 약속), each with its period, its quote and the kind of document it came from:
  - payout or return-ratio targets ("2030년까지 환원율 50%");
  - DPS floors or raise promises;
  - buyback and cancellation plans;
  - ROE or return targets from 기업가치 제고 계획;
  - earnings guidance (US and tobacco names).

## Part D — Reading events and changes

1. **Acquisitions.** Collect them here (v18.0 Part G does not list them): 타법인주식및출자증권양수결정 from DART's
   주요사항보고서 API, and the exchange filing 타법인주식및출자증권취득결정 for deals below the 주요사항보고서 threshold.
   - **Large:** price ÷ the buyer's equity ≥ 10%. Jack approves the threshold in the PR.
   - **Unrelated:** compare the target's stated 주요사업 with the buyer's industry and business lines. Keep both quotes
     as the receipt.
   - Large and unrelated → **지켜봐요 with "확인 필요"**, until the user confirms. This matches `REDESIGN.md` §4.2: the
     user's rule book lists it as a sell condition, but "unrelated" needs reading, so the engine never applies
     규칙 깨짐 on its own.
2. **Promise changes.** Compare a promise only with the next document **of the same kind**, or with a filing that
   explicitly revises it. For example, a 기업가치 제고 계획 is compared with the next 기업가치 제고 계획.
   - `kept`: same or stronger.
   - `weakened`: lower target, later date, or vaguer wording.
   - `dropped`: removed from that kind of document. Not being mentioned in a different kind of document is not
     "dropped".
   - `weakened` or `dropped` → 지켜봐요, with both quotes side by side, until the user confirms.
   - Exceptions, which follow their own rule's setting instead:
     - a numeric promise checked against structured data, for example DPS +10% against the DART dividend figure;
     - a numeric policy target that falls below a number in the user's rule, for example 코웨이's return-ratio target
       set below 40%. That target is a status field (Part A3), so the two-key rule applies.

## Part E — Theme tags

`data/themes.csv` holds the mockup's 45 themes, with these columns:
- id, group, and Korean name (from the approved copy);
- search words and markets;
- type, KSIC codes (type I), and the one-line definition below.

**Types:**
- **I** = industry, by **KSIC codes listed in `themes.csv`**, so v18.0's merging of small industry groups never changes
  a theme.
- **R** = current revenue ≥ 10% of consolidated revenue from the named business (Decision 2).
  - Use the most specific breakdown the report gives: product line first, then segment.
  - If no product line isolates the business, a named segment of ≥ 10% qualifies when its description names that
    business as the segment's **main** business (first-named or largest stated line). A segment that merely lists the
    business among others does not qualify. The receipt then says "부문 기준".
- **P** = a drug candidate in clinical phase 2 or later.
- **D** = a data rule with a receipt.

**Holding companies** (the v18.0 holding-company group) get themes only from businesses they run themselves. Listed

## Wiring, gate and validation

- **Wiring:** every new published file goes into the gate, the deploy, the watchdog and CLAUDE.md rule 3, **in the same
  PR** (as in v18.0).
- **When v18.2's checks fail:**
  - v18.2's values live in their own files.
  - Proposed behaviour: the run keeps the last good v18.2 files, with their dates, and still publishes prices. The
    failure is logged loudly and the watchdog shows it.
  - This changes `validate_data.py`'s all-or-nothing behaviour for these files, so propose it under **안전 규칙 변경**
    with the reason.
  - Until Jack approves it, a v18.2 failure fails the whole run, which is the frozen behaviour.
- **Storage:** per-stock facts load on demand, outside the files the app loads on start. Theme membership is small and
  loads with 덱 짜기. Propose the layout and sizes in Plan mode.
- **Extend `validate_data.py`:**
  - provenance and a stored "pass" quote check on every published value;
  - bounds;
  - staleness flags;
  - the must-have assertions above;
  - coverage per field and per theme, logged as "· 지역별 매출: 1,184 / 1,362".
- **Thresholds:** new ones go under **안전 규칙 변경** with the first real run's numbers. Jack approves them before merge.
