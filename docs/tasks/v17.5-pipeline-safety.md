## The standard Jack set

Wrong or stale data reaching users is one of the two worst things that can happen to 뱁새. Three guarantees must hold
even when a data source changes behind our back:

1. **Broken or wrong data never reaches users.** Worst case, the last good data stays up, clearly dated.
2. **Every failure is loud.** A red run, the same day, with the reason in plain words.
3. **The app never pretends.** Every number shown is either live and dated, or clearly labeled as not live.

v17.5 delivers correct numbers, guarantees 1 and 3, and the "red run" half of 2. v17.6 adds independent monitoring,
automatic tests on every change, and a protected `main`.

Out of scope: features and layout. New copy only as listed in § F. Don't touch guide content.

## A. Korean prices = official closing prices, one consistent date

Verified problem: published prices are mid-session, not closes. The 10/28 run published 삼성전자 at 234,000원; the
official close was 222,500원 on 10/27 and 244,000원 on 10/28. Only ~10% of Korean prices equal any official close.
Cause: GitHub starts the job during market hours, and the Naver price series includes the forming day's bar and
after-hours (Nextrade) trades.

1. **All dates in KST:** `datetime.now(ZoneInfo("Asia/Seoul"))`. Never use `date.today()` on the runner (it's UTC).
2. **`load_kr_listing()`**: choose the latest **final** listing file before today (KST) from
   `https://raw.githubusercontent.com/FinanceData/fdr_krx_data_cache/refs/heads/master/data/listing/krx/{YYYY-MM-DD}.csv`.
   - **Final** means ≥ 90% of rows have numeric `Marcap > 0`, **and** the file's last commit is at or after 18:00 KST
     on that date. Check via GitHub's REST commits API with `path=…`, authenticated with the workflow token.
     The ~13:00 intraday version also looks complete but carries intraday prices.
   - If finality can't be checked, use the most recent file whose next trading day's file already exists.
   - Walk back up to 10 calendar days.
   - Log it, e.g. `· 종목 목록: 2026-10-29 최종본 (19:58 KST 커밋, 2,872종목, 시총 100%)`.
3. **`pxDate` = that file's date.** Written at the top level of `data.json` and `corp.json`.
4. **KR `price` = that file's `Close`.**
   - Cut every price series (stocks, KS11, bond ETFs, KR-side FX use) to dates ≤ `pxDate` before computing returns,
     beta, vol, 52-week range, r1/r3/r36.
   - `cap` = Close × `Stocks`, cross-checked against the file's `Marcap` (warn if > 1% off). `val` (억원) from `Amount`.
5. **Fallbacks:**
   - `fdr.StockListing("KRX")` with the same final-file checks.
   - Last resort: previous `data.json`. That path currently crashes: `OUT_DATA` is undefined at fetch_data.py:1094.
     Fix it and make it NaN-safe. If the last-resort path is used two runs in a row, fail hard.
6. Select `MAX_KR` by market cap from the final file. Assert 005930, 000660, 005380, 015760 and 105560 are present.
7. `_fin(x)` → `float` or `None` for None/NaN/±inf/non-numeric. Replace every `float(x or 0)` / `(x or 0)` on numbers.
   List each site in the PR.

## B. Other data that is silently wrong or stale (all verified)

1. **US prices.**
   - yfinance treats `end` as exclusive, so `end = date.today()` drops the latest session. On 10/10 and 10/14, 776/777
     and 777/778 US prices were unchanged while `asOf` moved forward.
   - Use `end` = today (KST) + 1 day.
   - Write `usPxDate` = the last `^GSPC` bar used.
2. **Units.** US `cap` is stored as USD/1e12 (trillions of dollars) and US `val` mixes USD with 억. Korean `cap` is in
   조원.
   - Store US cap and val in 원 using the run's `fx`, with the same units as KR, and document the units.
   - Rank factors **within each market** (KR separately, US separately). `add_percentiles(kr + us)` at
     fetch_data.py:1496 mixes them; 899 Korean stocks' 가치 score moves > 10 points as a result.
3. **Embedded prices leaking into live views.** `mergeStocks` (`detail.jsx`) appends every `BASE_STOCKS` entry with no
   live match. 069500, 379800, 04020000 (금현물), 132030 and 144600 are never in `data.json`, so the 금·은 block and
   two ETFs always show embedded 2025-era prices.
   - Add those five to the pipeline. For 04020000, find the right KRX gold-spot source or derive it from
     `macro.json` gold in 원/g, and document which.
   - Mark every merged entry `live: true/false`.
4. **Section dates.** `macro.json` and `disc.json` set `asOf` = run date even when their content is old.
   - Write `curve.date` (latest ECOS observation), `disc.newest` (latest disclosure date) and `disc.listOk` (whether
     the DART list call succeeded).
   - Each tab shows its own content date, not the run date.
5. **TTM quarter switch.** `enrich_with_dart` probes one quarter via 삼성전자 and applies it to all companies. When
   Samsung's 3Q report appears (deadline 11/16), every company that hasn't filed yet loses TTM, with no fallback.
   - Per-company fallback 3Q → 2Q → 1Q, recorded per company in `bq`.
   - Treat the quarter as current only when ≥ 70% of the 100 largest companies have filed it.

## C. DART quota and caching (needed now, or testing itself breaks the data)

One full run is ≈ 2,500 companies × 4–8 calls + up to 1,400 disclosure calls — close to OpenDART's ~20,000/day limit.
Evidence: 8/19 had two runs, and the second (`b076177`) has PER coverage 20% and PBR 26%.

- Log DART status counts. If `020` (quota) appears, fail with `!! DART 일일 한도 초과`.
- Cache DART results with `actions/cache`:
  - key `dart-cache-v1-${{ github.run_id }}`, restore-keys `dart-cache-v1-`;
  - save with `actions/cache/save` and `if: always()` right after the fetch step. This is allowed: the safety ban on
    `always()` applies to publish/commit steps, not cache saves.
- Cache rules:
  - per (corp_code, bsns_year, reprt_code, fs_div);
  - a found report is final;
  - "not filed yet" is retried at most every 7 days (daily during the 7 days before a filing deadline);
  - entries older than 90 days are re-validated in a rolling batch (≤ 300/day) to catch 정정공시.
- `workflow_dispatch` inputs:
  - `dry_run` (default false) — skip commit/push;
  - `dart` = `cache` (default: cached results plus only missing entries) or `full`.
- Rule: at most one `dart=full` run per KST day.
- `timeout-minutes: 300` as a backstop. Phase timers in the log, e.g. `⏱ 가격 18m 40s · DART 6m 12s`.
  Target: steady-state ≤ 45 min.

## E. Validation gate — `validate_data.py`

Runs after `fetch_data.py`, before commit. Exit 1 on any hard failure. Importable, with a `--live` mode for v17.6's
watchdog (absolute checks only).

"Previous" = the last published files: `HEAD` for now, the `data` branch after v17.6. Previous unreadable → relative
checks fail hard, **unless** `--bootstrap` is passed. That flag exists only for the first run after this PR. It must be
visible in the log and passed by a manual workflow input, never by default.

Hard checks (thresholds calibrated on the 2026-10-17 files):
- **Parse:** all four files parse strictly (`parse_constant` raises). Any NaN/Infinity anywhere = fail.
- **Correct date:**
  - `validate_data.py` independently computes the latest final listing date before today (KST), using the same rule
    as A2 but its own code.
  - `pxDate` must equal it. This is holiday-proof with no calendar. Today's bug (reading the wrong day) fails here.
  - `pxDate` ≥ previous `pxDate`.
- **Correct prices:**
  - ≥ 99% of KR prices equal that final file's `Close`;
  - 005930 matches exactly;
  - KS11's last date used == `pxDate`.
- **US freshness:**
  - `usPxDate` ≤ 4 days old;
  - when `usPxDate` advanced, ≤ 20% of US prices unchanged vs previous.
- **FX:** 900 < fx < 2,000 and |Δfx vs previous| ≤ 5%.
- **Risk-free rate:** `settings.rfSrc` is not the fallback (after Step 0 fixes it).
- **Rates:** `curve.date` ≤ 7 days old (after Step 0 fixes ECOS).
- **Universe:**
  - KR ≥ 2,300 and within ±10% of previous;
  - US ≥ 500 and within ±15%;
  - bonds ≥ 7 and equal to previous (8 after Step 0's fix).
- **Must-have stocks:** 005930, 000660, 005380, 015760, 105560, 035420, 012450 with `price > 0` and `cap > 0`. The five
  added in B3 are present.
- **Field coverage (KR):**
  - Absolute: price ≥ 99%, cap ≥ 99%, beta ≥ 95%, vol ≥ 95%, pbr ≥ 85%, roe ≥ 80%, per ≥ 50%, each of
    `vz qz mz pz lz` ≥ 85%.
  - Relative: no field drops > 10 points vs previous.
- **Price moves:** let n = number of final listing files dated after the previous `pxDate` (normally 1). ≤ 0.5% of KR
  stocks may move more than (1.3ⁿ − 1) vs previous. KRX's daily limit is ±30%.
- **Ranking:** 005930 in `popular[:20]`; the 20 largest KR caps are not in alphabetical order.
- **corp.json:**
  - ≥ 2,000 companies, ≥ 20 sectors;
  - 005930 has `per` or `pbr`;
  - TTM coverage ≥ 50% hard, warn below 80% (per-company fallback per B5).

Soft (warn): `disc.listOk` false; anything within 2 points of a hard threshold.
